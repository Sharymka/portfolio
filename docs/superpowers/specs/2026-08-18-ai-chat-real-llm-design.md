# Ask My AI: переход на настоящую LLM

**Статус:** дизайн согласован, ожидает вычитки перед планом реализации.
**Дата:** 2026-08-18

## 1. Контекст

Секция «Ask My AI» сейчас (`src/features/ask-ai-chat`) — клиентский keyword-matcher: массив `QA_DATA` с вопросом, списком ключевых слов и готовым ответом; `answerFor` ищет первое совпадение подстроки. Это осознанный временный MVP — зафиксировано в `docs/superpowers/plans/2026-08-17-ask-my-ai.md`: «No real LLM call — explicitly out of scope per spec §14».

Полноценная архитектура для настоящего AI-чата уже была спроектирована раньше в `docs/technical-research.md` §2.16, но не реализована. Этот документ — актуализация того решения плюс конкретика, которой там не было (языковая стратегия, точное содержимое профиля).

**Отличия от `technical-research.md` §2.16:**
- Провайдер подтверждён повторно: **Google Gemini** (`gemini-2.5-flash-lite`) — бесплатный тариф, без риска счёта.
- Новое решение, которого не было в исходном документе: контент чата хранится **только на русском**, языковая версия ответа — инструкция в system prompt, а не ручной перевод (в отличие от текста остального сайта, где RU/EN дублируются вручную, например `CASES`/`CASES_EN`).
- Rate limiting подтверждён как launch-blocking (не «добавить позже»), как и было рекомендовано изначально.

## 2. Цели / не-цели

**Цели:**
- Чат отвечает на открытые вопросы о Светлане, а не только на 4 заготовленных.
- Ответы строго на основе предоставленных фактов; при нехватке информации — честное «уточните у Светланы лично», без додумывания.
- Стриминг ответа (токен за токеном), как в стандартном UX AI-чатов.
- Один источник контента на двух языках сайта — без ручного дублирования.
- Защита от злоупотреблений и превышения бесплатной квоты — до публичного релиза, не после.

**Не цели (осознанно не делаем):**
- RAG / векторный поиск — объём контента (био + 3 кейса + стек + подход) целиком помещается в system prompt.
- Персистентность истории переписки между перезагрузками страницы — не нужна для одностраничного портфолио.
- Админка/CMS для редактирования профиля — контент остаётся кодом (TS-объект), правки — обычный PR, как и весь остальной контент сайта.
- Аутентификация пользователей чата.

## 3. Архитектура

```
Client (AskAiChat, useChat)
  → POST /api/chat { messages, lang }
    → Route Handler (src/app/api/chat/route.ts)
      → rate limit check (Upstash, по IP)
      → 429 если превышен лимит → friendly-ответ клиенту
      → сборка system prompt: entities/profile + CASES + Skills/Think (RU) + языковая инструкция + guardrails
      → streamText(google('gemini-2.5-flash-lite'), { system, messages })
    ← стриминговый ответ
  ← useChat рендерит токены по мере поступления
```

**Новые модули:**
- `src/app/api/chat/route.ts` — Route Handler.
- `src/entities/profile/model/profile.ts` (+ `profile.test.ts`, `index.ts`) — структурированные факты о Светлане, RU-only.
- `src/features/ask-ai-chat/ask-ai-chat.tsx` — переписывается на `useChat` из `@ai-sdk/react` вместо ручного `useState` + `answerFor`.

**Удаляется:**
- `src/features/ask-ai-chat/model/qa-data.ts` и `qa-data.test.ts` — keyword-matcher больше не нужен.
- Тесты, завязанные на конкретные канонические RU/EN-ответы (детерминированного поведения больше нет — ответ генерирует модель).

**Новые зависимости:**
- `ai`, `@ai-sdk/google`, `@ai-sdk/react` — вызов Gemini и стриминг (Vercel AI SDK).
- `@upstash/ratelimit`, `@upstash/redis` — rate limiting на бесплатном тарифе Upstash.

**Новые переменные окружения** (`.env.local`, уже покрыт `.gitignore`):
- `GOOGLE_GENERATIVE_AI_API_KEY` — это имя переменной ожидает `@ai-sdk/google` по умолчанию. Ключ уже создан и добавлен в `.env.local` — на этапе реализации нужно свериться, что переменная называется именно так (переименовать при необходимости).
- `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` — потребуется завести бесплатную Redis-базу на upstash.com (ещё не сделано).
- На проде (Vercel) — те же переменные добавляются в настройках проекта перед деплоем этой фичи.

## 4. Модель контента (`entities/profile`)

```ts

  strengths: string;
  currentlyLearning: string;
  english: string;
  teamwork: string;
  agile: string;
  documents: string;
  personal: string;
  boundaries: string[];

```

Черновик значений (на основе ответов Светланы, слово в слово по смыслу, без додумывания):

- **career**: техническое образование не по IT — ЮФУ, направление, связанное с нанотехнологиями; работала в инженерной/полупроводниковой сфере; сменила направление на разработку осознанно. Frontend изучала через GeekBrains (индивидуальные и командные проекты, Scrum), затем стажировка в Itransition с полноценным приложением и взаимодействием с backend. Есть опыт backend на Express/MySQL/Sequelize, но основное направление — frontend.
- **experience**: текущий коммерческий опыт — маркетплейс объявлений и аукционов (Next.js/React/TS/Redux Toolkit/RTK Query), в команде с backend, дизайном и продуктом, участвует в обсуждении API и code review. До этого — стажировка в Itransition (Questionnaire App). GeekBrains — явно учебные/командные проекты, не коммерческий опыт.
- **status**: активно ищет работу; портфолио сделано именно для поиска следующей позиции.
- **workFormat**: приоритет — удалённая работа; другие форматы — индивидуально; текущая локация — Тбилиси; конкретные города для переезда не называть, пока не определены.
- **preferences**: Frontend Developer, React/Next.js/TypeScript; важнее команда и качество разработки, чем размер компании; интересны продуктовые задачи, где frontend — существенная часть продукта; хочет расти рядом с более опытными разработчиками; без жёстких ограничений «только стартап»/«только крупная компания».
- **strengths**: быстро погружается в чужой код и сложную frontend-логику; сильна в React/Next.js/TypeScript/Redux Toolkit/RTK Query; понимает взаимодействие frontend↔backend; внимательна к состояниям интерфейса, ошибкам, кешированию, сценариям; не ограничивается «по макету» — понимает, зачем нужна функция.
- **currentlyLearning**: углубляет frontend-архитектуру, Next.js, производительность, работу с состоянием.
- **english**: Upper-Intermediate, регулярные занятия с преподавателем; не заявлять Fluent/Advanced.
- **teamwork**: есть опыт code review и обсуждения архитектурных решений в команде; менторство junior и систематический pair programming — явно не заявлять (нет такого опыта).
- **agile**: есть опыт работы в Agile/Scrum и в учёбе, и в текущем проекте; относится нормально — важно, чтобы процесс помогал команде, а не был самоцелью.
- **documents**: диплом — ЮФУ, направление связано с нанотехнологиями. Сертификат — «Certificate of Participation» от Itransition за бесплатное обучение «Commercial Software Development — JavaScript» (дистанционно, 7 ноября 2024) — это подтверждение участия в обучении, **не формальная профессиональная сертификация** (на самом документе явно написано «Not a legal document»).
- **personal**: сменила профессиональное направление осознанно — не боится начинать сложное с нуля; интересно разбираться, как технологии работают изнутри. Хобби: кулинарные эксперименты с новыми кухнями, хайкинг, сноуборд зимой, чтение, самостоятельное изучение английского.
- **boundaries** (дословный список — жёсткий guardrail в system prompt):
  1. не придумывать и не увеличивать коммерческий опыт;
  2. не превращать обучение в коммерческую работу;
  3. не приписывать технологии, с которыми не работала;
  4. не заявлять опыт менторства/управления командой;
  5. не называть английский Fluent/Advanced;
  6. не придумывать причины ухода из компаний;
  7. не называть зарплатные ожидания самостоятельно — отвечать, что зависят от позиции/условий и обсуждаются индивидуально;
  8. не обещать готовность к переезду в конкретную страну/город;
  9. не раскрывать лишние подробности личной/семейной жизни;
  10. при нехватке информации — прямо сказать, что вопрос стоит уточнить у Светланы лично, а не придумывать ответ.

Кейсы, стек и подход к работе **не дублируются** в `profile.ts` — Route Handler на каждый запрос переиспользует уже существующие `CASES` (`src/entities/case`) и RU-объекты `COPY.ru` из `Skills`/`Think`.

## 5. Языковая стратегия

Клиент передаёт текущий `lang` (`'ru' | 'en'`, из `LanguageProvider`) в теле запроса. Route Handler добавляет в system prompt явную инструкцию: «Отвечай на {ru|en}, независимо от языка, на котором задан вопрос» — так ответ всегда совпадает с языком интерфейса, даже если пользователь напишет вопрос не на том языке.

Все факты в system prompt — на русском; перевод на лету делает сама модель. Это соответствует уже подтверждённому решению — не дублировать контент вручную, как для остального сайта.

## 6. UI

Визуальная оболочка `AskAiChat` не меняется: карточка, пузыри сообщений, кнопки быстрых вопросов, поле ввода + кнопка отправки.

Меняются внутренности:
- `useChat({ api: '/api/chat', body: { lang } })` из `@ai-sdk/react` заменяет ручной `useState<Message[]>` + `answerFor`.
- Стартовое приветствие остаётся статичной локальной строкой в UI (не уходит в API как сообщение) — так же, как сейчас.
- 4 кнопки быстрых вопросов остаются те же по темам (стек, кейс-гордость, подход к сложным задачам, переезд/удалёнка); по клику текст вопроса реально отправляется в чат через `useChat`, а не ищется в таблице.
- Пока модель стримит ответ — текст последнего AI-сообщения дозаполняется по мере поступления токенов (стандартное поведение `useChat`).

**Важное разграничение:** только сам разговор с моделью (её ответы) переводится на лету по инструкции в system prompt (п.5). UI-обвязка — стартовое приветствие, текст кнопок быстрых вопросов, плейсхолдер поля ввода, подпись кнопки отправки — остаётся обычным жёстко закодированным `COPY = { ru, en }`-объектом, как во всех остальных секциях сайта. Модель не переводит интерфейс, только свои ответы.

## 7. Guardrails против галлюцинаций

System prompt, помимо фактов из п.4, содержит явную инструкцию:

> Отвечай только на основе фактов, перечисленных выше. Если информации недостаточно, чтобы честно ответить — прямо скажи, что этот вопрос стоит уточнить у Светланы лично, и не придумывай ответ. Никогда не нарушай ограничения из списка «boundaries».

Это главный риск фичи (зафиксирован ещё в `technical-research.md`, риск №10): недостоверный ответ подрывает доверие сильнее, чем отсутствие ответа.

## 8. Обработка ошибок

- **Квота Gemini исчерпана / ошибка API** — `useChat`'s `onError` показывает в чате honest fallback-бабл (RU/EN): «ИИ-ассистент временно недоступен, попробуйте позже, или напишите мне напрямую» — без ссылки на форму (форма удалена), со ссылкой на mailto/Telegram.
- **Rate limit превышен** (Upstash) — Route Handler возвращает 429 с понятным сообщением; клиент показывает его тем же fallback-стилем, не голой ошибкой.
- **Валидация ввода** — сообщение длиннее разумного предела (например, 500 символов) отклоняется на сервере с понятным ответом, не уходит в модель.

**Лимит по умолчанию:** 10 запросов на IP за 10 минут (sliding window через `@upstash/ratelimit`) — консервативная защита для сайта с ожидаемо небольшим трафиком; число можно скорректировать после реального использования.

## 9. Тестирование

- **Route Handler** — юнит-тест с замоканной моделью (Vercel AI SDK предоставляет мок-провайдер для тестов), без реальных сетевых вызовов. Проверяем: system prompt содержит факты из `profile.ts`, список boundaries, правильную языковую инструкцию под переданный `lang`.
- **`AskAiChat`** — мокаем `useChat`/fetch к `/api/chat`. Проверяем: клик по быстрому вопросу отправляет сообщение, сообщения рендерятся, ошибка/rate-limit показывает fallback, стартовое приветствие показывается сразу.
- Старые тесты на конкретные канонические ответы (`qa-data.test.ts`, соответствующие проверки в `ask-ai-chat.test.tsx`) удаляются — поведение больше не детерминировано.
- CI не делает реальных вызовов к Gemini/Upstash — только моки, как и весь остальной тестовый периметр проекта.
