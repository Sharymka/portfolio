## 1. Что решено сегодня и что это меняет

**Структура сайта (подтверждено, конфликта с research нет):** гибрид — одна прокручиваемая главная страница (Hero → «обо мне» → навыки → сетка проектов → контакты, «как думаю» и AI-чат — отдельным заходом позже) + отдельные страницы кейсов `/projects/[slug]` для каждого проекта. Это то же самое, что уже зафиксировано в `technical-research.md` §3.5 — пользователь подтвердил это направление явно.

**Амендмент к `technical-research.md` §2.8 (i18n):** ранее было решено «английский первым» для порядка наполнения реального контента. Сегодня явно решено обратное для этого дизайн-прохода — **весь текст ниже написан на русском первым**, потому что резюме и разговор с пользователем — на русском. Архитектура i18n (роутинг `/en/`, `/ru/`, структура `messages/en.json` + `messages/ru.json`) не меняется — меняется только порядок, в котором заполняется реальный текст: русский теперь идёт первым, английский — вторым этапом.

**Сегодняшний скоуп** — 5 из 6 секций главной страницы: Hero, «обо мне» (ценность), Навыки, Сетка проектов, Контакты. «Как думаю» и AI-чат («Ask My AI») сознательно оставлены за скобками — это отдельная, более сложная фича с открытым вопросом по LLM-провайдеру (см. `technical-research.md` §3.8), не блокирует запуск основного каркаса.

## 2. Общая концепция скролла (применяется ко всем секциям ниже)

Пользователь явно запросил ощущение «единого полотна», а не набора сменяющих друг друга блоков, плюс визуальный «вау»-эффект. Решение:

- **Фон — один непрерывный слой на весь скролл**, не сбрасывается между секциями. Тил→navy градиент (уже зафиксирован в дизайн-токенах) медленно смещается/дрейфует по мере скролла — это и даёт ощущение полотна, а не набора карточек.
- **Появление секции = подсветка, не увеличение текста.** Свечение (glow) мягко разгорается позади заголовка секции при входе в viewport, затем сам блок контента поднимается и проявляется (fade + небольшой сдвиг вверх). Текст **не** масштабируется и не анимируется посимвольно — это прямо противоречило бы уже принятому правилу «не анимировать текст, критичный для чтения» (`portfolio-design-research.md`, `visual-style-research.md`).
- **Reveal-паттерн для повторяющихся элементов (карточки, теги, строки проектов) — вариант A: естественный scroll-reveal с интервалами**, без scroll-джекинга/pinning. Между элементами — щедрый вертикальный отступ, каждый элемент проявляется по факту входа в viewport через `whileInView` (Motion). Альтернатива со sticky/pinned-секцией (эффектнее, но хрупкая на мобильных и не заложена в текущий технический план) — рассмотрена и отклонена.
- Обязательные ограничители не меняются: полный откат к мгновенному появлению без glow/дрейфа при `prefers-reduced-motion`, бюджет Lighthouse/CWV в CI следит за тем, чтобы дрейф фона не просаживал INP.

Технически всё это укладывается в уже согласованный инструмент (Motion, `whileInView`, layered by section importance) — новых зависимостей не добавляется.

## 4. «Обо мне» / ценность

Без отдельного крупного заголовка секции — прямое продолжение первого экрана, только короткая вводная строка перед карточками: **«Что я приношу в проект:»**

**Формат — не статичный список, а последовательность из 5 отдельно проявляющихся карточек** (reveal-паттерн A из раздела 2: щедрые отступы между карточками, каждая — glow + fade-up при входе в viewport). Текст каждой карточки максимально сокращён до одной строки-заголовка:

1. Синхронизировала фильтры каталога между Redux, URL и API — состояние не теряется при навигации.
2. Перевела главную ленту на RTK Query — повторные запросы упали с 3-4 до 0.
3. Собрала модуль отзывов: бесконечная пагинация, кастомный кеш, inline-редактирование.
4. Ускорила первую загрузку lazy loading и code splitting — меньше JS на старте.
5. Выстроила AI-пайплайн в Cursor: брейншторм → дизайн → код → ревью, под своим контролем.

Пункт 4 сознательно **без конкретного процента** (например, «на 40%») — цифра не была подтверждена как измеренная, а недостоверная метрика подрывает доверие сильнее, чем её отсутствие (тот же принцип честности, что уже зафиксирован для AI-чата в `technical-research.md` §2.16, риск 10). Если появится реальное измерение (например, из Lighthouse до/после) — вставить вместо общей формулировки.

## 5. Навыки

**Формат — гибрид: короткая вводная строка с результатами + категоризированные теги** (не карточки компетенций и не голое облако тегов — выбран средний вариант, чтобы совместить «ценность, а не список инструментов» из research с прямым запросом пользователя показать стек).

**Вводная строка** (не дублирует достижения из блока «обо мне» — про широту стека и качество):

**«Помимо React и Next.js — работаю с формами (React Hook Form + Zod), покрываю функциональность unit-тестами, веду Storybook-сценарии для переиспользуемых компонентов и слежу за базовой accessibility: семантика, фокус, доступные формы.»**

**Категоризированные теги** (шрифт JetBrains Mono для самих тегов, как зафиксировано в `visual-style-research.md`):

```
Core              [ React ] [ TypeScript ] [ Next.js ] [ JavaScript (ES6+) ] [ HTML5 ]
State & Data      [ Redux Toolkit ] [ RTK Query ] [ REST API ] [ SSR / Hydration ]
                  [ client-side caching ] [ React Hook Form ] [ Zod ]
Тесты и качество  [ Vitest ] [ Storybook ] [ Git ] [ CI/CD ] [ Feature-Sliced Design ]
Backend-смежное   [ Node.js ] [ Express ] [ PHP ] [ Laravel ] [ PostgreSQL ]
                  [ MySQL ] [ Docker ] [ Cloudinary ]
```

Плюс отдельный малозаметный ряд ниже основных категорий: **«Также работала с:»** `Vue.js`, `Material UI` — не входят в основное React/Next.js-позиционирование, но пользователь подтвердил, что хочет их оставить.

Уточнение по честности: PHP и Laravel в Backend-смежное включены как полноценные теги, потому что пользователь подтвердил, что писала PHP/Laravel-код сама (проект myHotel), а не только интегрировала frontend с готовым API.

**Появление:** категории проявляются по одной при скролле (glow + fade, тот же паттерн A), теги внутри категории — с лёгким stagger (~60-80мс между тегами). При наведении на тег — едва заметное тил-свечение обводки (тот же hover-приём, что уже есть у `Button`).

## 6. Сетка проектов

**Layout — вариант B: чередующиеся полноширинные строки** (изображение слева/справа поочерёдно), а не однородная сетка карточек — при 3-5 кейсах это даёт каждой истории визуальный вес и соответствует принципу «кейсы как история, а не список скриншотов» из `portfolio-design-research.md`.

**Порядок — по силе сигнала, не хронологический**: сначала самый сильный и текущий бизнес-кейс с измеримым результатом, дальше по убыванию масштаба.
