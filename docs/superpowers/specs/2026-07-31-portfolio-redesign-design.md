Дата: 2026-07-31
Статус: согласовано с пользователем в диалоге, готово к ревью перед переходом к implementation-плану.

**Это не амендмент, а замена направления.** Документ заменяет `2026-07-24-homepage-core-frame-design.md` и `2026-07-24-warm-accent-palette-design.md` целиком — тёмная slate-палитра (`#0F172A`) с teal→оранжевым акцентом, 5-карточная секция «обо мне» и структура «главная + `/projects/[slug]`» из этих документов больше не действуют. **Обновление 2026-08-03:** по решению пользователя этот документ теперь единственный источник правды по дизайну. `2026-07-24-homepage-core-frame-design.md`, `2026-07-24-warm-accent-palette-design.md`, `portfolio-design-research.md` и `visual-style-research.md` физически удалены из репозитория (не просто помечены устаревшими) — вся история, которая раньше жила в них, свёрнута в этот документ. `technical-research.md` не удалён — он про стек/архитектуру, не про дизайн.

## 1. Шрифты — критичная правка макета

Макет как есть использует **Caprasimo** (заголовки) и **Figtree** (текст). Проверено по официальному реестру Google Fonts (`google/fonts`, `METADATA.pb`): у обоих шрифтов заявлены только `latin`/`latin-ext` — **кириллицы нет физически**, ни одного глифа. Подтверждено эмпирически пользователем через DevTools → Computed → Rendered Fonts на живом превью макета: кириллический текст, объявленный как `Figtree`, фактически отрисован шрифтом `Ubuntu` (65 глиф) — то есть системным шрифтом ОС посетителя, а не Figtree (24 глифа — то немногое, что Figtree реально нарисовал). Это тот же класс проблемы, что уже случился с Space Grotesk в этом проекте (см. `2026-07-17-portfolio-foundation.md`).

**Решение — замена по всему сайту:**

| Роль | Было в макете | Стало |
|---|---|---|
| Заголовки (h1-h6) | Caprasimo | **Unbounded** (500/700/800) |
| Текст, теги, кнопки, чат | Figtree | **Nunito** |

Оба варианта подтверждены официально (`subsets: cyrillic, cyrillic-ext`). Unbounded уже используется в макете для `h1` — просто расширяется на все заголовки вместо одного. Nunito выбран как ближайший по характеру к задумке Figtree (тёплый, округлый, дружелюбный) среди кириллических кандидатов.

## 2. Структура страницы

Один скроллящийся лендинг, без отдельных страниц кейсов (`/projects/[slug]` из старого решения — вне скоупа, в макете их нет). Секции сверху вниз:

1. Nav (sticky) — **включая ссылку на «Документы»**, которой не было в исходном макете (см. §7)
2. Hero
3. «Обо мне» — 7 карточек ценности (а не 5, как в старом решении)
4. Навыки
5. Кейсы (избранные)
6. «Как думаю»
7. Ask My AI (чат)
8. Документы
9. Контакты
10. Footer

Фон — один непрерывный слой с `bgBreathe`-дрейфом на весь скролл (концепция «единого полотна» из старого решения сохраняется, реализация — как в макете: `background-position` анимация, а не тил→navy, а кремовый/акцентный градиент).

## 3. Hero

Layout как в макете: текст слева, фото справа, два плавающих blur-blob'а на фоне (`floatBlob`), градиентная CTA-кнопка со свечением (`gradientShift` + `glowPulse`).

**Фото профиля меняется** на реальный портрет, присланный пользователем 2026-07-31 (тёплый нейтральный фон, растение, ноутбук) — заменяет использованные в макете AI-сгенерированные Nupix-фото в холодной гамме. Новое фото визуально ближе к тёплой кремовой палитре, чем исходные — замена не требует компромиссов.

Текст, роль, тег-лейбл, CTA «Смотреть кейсы» — как в макете, без изменений.

## 4. «Обо мне» — 7 карточек ценности

Ровно как в макете: 7 карточек в auto-fit гриде, органичные скруглённые иконки (border-radius blob-формы), reveal по одной при скролле. Текст карточек — как в макете (устраняю лишние запросы, собираю сложные модули, ускоряю загрузку, AI как инженерный инструмент, архитектура приложений, синхронизация состояния, тесты). Это заменяет 5-пунктовый список из старого решения.

## 5. Навыки

Категоризированные теги как в макете (Core / State & Data / Тесты и качество / Backend-смежное / «Также работала с»). Без изменений относительно макета.

## 6. Кейсы — карточки + карусель скриншотов

Три кейса, порядок и overview-текст (роль → цель → результат → детали → теги) как в макете и как в резюме (`Хайрудинова Светлана.pdf`, обновлено 09.07.2026 — сверено, текст совпадает дословно).

**Новое сверх макета: клик по превью открывает карусель скриншотов.** В макете на кейс — один `image-slot` placeholder; по факту у пользователя есть реальные скриншоты для всех трёх кейсов:

- **Экосистема Альфа** (маркетплейс «Объявления & Аукционы») — 12 скринов: каталог/новинки, карточка товара, модалка ставки, вход, создание объявления, диалог сообщений, список сообщений, уведомления, настройки профиля, каталог с фильтрами, профиль продавца с отзывами
- **Questionnaire App** (Itransition) — 7 скринов: галерея шаблонов, детали шаблона, конструктор формы, выбор типа вопроса, выбор тегов, прохождение опроса, вход
- **myHotel** — 3 скрина: дашборд администратора, таблица задач, страница логина

Публичные продукты (маркетплейс, приложение опросов, тестовый прототип гостиницы) — без NDA-ограничений на показ, все три можно показывать открыто.

**Поведение карусели:**
- Превью кейса остаётся как в макете (одна главная картинка + номер), но кликабельно
- Клик открывает модальное окно (lightbox) с каруселью: стрелки prev/next, счётчик «3 / 12», клавиатурная навигация (←/→, Esc закрывает)
- Фокус-трап внутри модалки, возврат фокуса на превью при закрытии (соответствует уже принятому в проекте принципу базовой accessibility)
- Анимация переключения слайдов отключается при `prefers-reduced-motion: reduce` (обязательный ограничитель, действующий во всём проекте)

## 7. Ссылка на «Документы» в навигации

В макете в nav есть только Навыки / Кейсы / Подход / Спросить ИИ / Связаться — секция `#documents` существует на странице, но не связана с nav. Добавляется ссылка **«Документы»** между «Спросить ИИ» и переключателем языка, ведёт на `#documents` (тот же паттерн scroll-to-anchor, что у остальных пунктов).

## 9. «Как думаю» и Ask My AI

Без изменений относительно макета: три пункта инженерного подхода (сначала ограничения → простота по умолчанию → развитие проекта); чат — клиентский keyword-matcher по `QA_DATA` из встроенного скрипта макета, без реального LLM-вызова. Вопрос выбора LLM-провайдера (`technical-research.md` §3.8) остаётся открытым и не блокирует эту реализацию — чат работает как полноценная (хоть и простая) фича, а не заглушка.

## 10. Контакты

Форма имя/email/сообщение с локальным состоянием «отправлено», как в макете — без реальной отправки на бэкенд (Resend/Server Action из старого плана — отложено, не блокирует). Email/Telegram-ссылки из старого решения (§7) заменяются формой, как в макете.

## 11. Переключатель RU/EN

Реализуется как в макете — визуальный (подсвечивает активную пилюлю RU/EN), без реального переключения текста интерфейса. Известное ограничение, не блокирует запуск; полноценный i18n (`next-intl`, уже заложенный в `technical-research.md`) — отдельная будущая задача.
